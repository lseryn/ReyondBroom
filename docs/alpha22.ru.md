# Фоновая сборка и просмотр BSP

[English](alpha22.md)

Открой **Run → Build map…** или нажми **F9**. Укажи папку `baseq3` в Game / resources и путь к `q3map2.exe` в окне сборки. Компилятор внешний, в архив редактора не включён.

Можно отдельно включить **Geometry / BSP**, **Visibility / VIS** и **Lighting / LIGHT**. Перед ними редактор экспортирует отдельный снимок документа, включая несохранённые изменения и исключение слоёв из экспорта. Исходный MAP не перезаписывается. Пока работает компилятор, можно продолжать редактирование; сам экспорт и загрузка готового BSP могут ненадолго занимать основной поток.

Если Geometry выключен, VIS/LIGHT используют предыдущий успешный BSP этой карты. Экспортируемый MAP должен полностью совпадать с предыдущим: в этой версии даже изменение light-энтити требует повторного Geometry. Изменения внешних шейдеров автоматически не отслеживаются. При сомнениях включай Geometry. Выбранные стадии и путь к компилятору сохраняются при запуске сборки.

Внизу 3D-вьюпорта отображаются стадия, время, последняя строка вывода, Cancel и Log. Полоса показывает число завершённых стадий, а не предполагаемый процент времени. Полный лог сохраняется в `build.log`. Отмена завершает дерево процессов; ошибка или отмена сохраняют предыдущий успешный результат.

**Show BSP** временно открывает один перспективный вид с текущей камерой: скомпилированный мир, lightmaps и неподвижные брашевые энтити. **Back to editing** возвращает раскладку, исходную геометрию, выделение и Undo/Redo. Команды редактирования возвращают режим редактирования автоматически. Сохранение сначала выходит из просмотра BSP; автобэкапы ждут возвращения к редактированию. Изменённый после экспорта документ помечается как более новая версия относительно BSP.

Игрового режима нет: двери не двигаются, триггеры не срабатывают, игровые объекты не симулируются. Используются подключённые ресурсы текущего проекта. Сборка только Geometry не рассчитывает освещение. После перезапуска редактора для просмотра нужно собрать карту заново.

Результаты находятся в `ftebroom/maps/ftebroom-build/<номер-сборки>/`: MAP-снимок, BSP, вспомогательные файлы и лог. Для каждой попытки создаётся отдельный каталог. Старые каталоги можно удалить после закрытия редактора.

## Что проверить

1. На копии герметичной карты включи все стадии. Проверь навигацию во время сборки, статус и лог во вьюпорте.
2. Нажми Show BSP: проверь освещение, тени, текстуры, небо и брашевые энтити. Проверь WASD и обзор ПКМ.
3. Вернись в редактирование: выделение, инструмент, сетка, раскладка нескольких видов и Undo/Redo должны сохраниться. Сделай Save As и открой сохранённую карту.
4. Собери только Geometry, затем только VIS, только LIGHT или обе стадии на неизменённой карте. Без выбранных стадий сборка должна отклоняться.
5. Измени карту и попробуй LIGHT без Geometry: редактор должен потребовать повторного Geometry.
6. Измени документ во время сборки: результат должен быть помечен как предыдущая версия. Открытие другой карты не должно приводить к её замене результатом старой сборки.
7. Отмени долгую сборку. Проверь неверный путь к компилятору и карту с утечкой при включённом VIS. Предыдущий успешный BSP должен сохраниться.
8. Сохрани карту во время просмотра BSP и открой MAP: должны сохраниться исходные редактируемые браши.

Также остаётся актуальным [общий список проверок редактора](checks-alpha21.ru.md). Этот релиз не означает полного закрытия всех критериев роадмапа.
