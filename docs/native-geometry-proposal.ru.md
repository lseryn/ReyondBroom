# Предложение: нативный API геометрии через буфер

[English](native-geometry-proposal.md)

Статус: предложение, не реализация. Причина: проверка призмы с 64 гранями в QC заняла около 4,9 мс при целевом пороге 2 мс.

Предлагается версия встроенной функции движка `brush_geometry_op(operation, inputPointer, inputBytes, outputPointer, outputCapacity)` и отдельный запрос необходимого размера результата. Массивы не передаются через cvar. Движок проверяет диапазоны памяти QC, размеры, переполнения и конечность чисел.

В буфере — числовые записи вершин, плоскостей, связей и индексов исходных граней. Строки материалов, UV и история остаются в QC. Нативная часть возвращает индекс исходной грани либо признак новой грани.

Первые операции: построение и проверка полиэдра из полупространств, выпуклая оболочка, разделение плоскостью. Функция возвращает статус, требуемый размер, число элементов и код ошибки. Она не меняет карту: применение успешного результата остаётся внутри существующей транзакции QC.

Внутри — вычисления двойной точности с проверкой результата после преобразования в float. Обязательны пределы входных и выходных данных без молчаливого усечения. QC-реализация остаётся эталоном и запасным путём.

Приёмка: одинаковые геометрические тесты для двух реализаций; некорректные буферы и переполнения; минимум 100 сложных операций и 500 отдельных брашей. Замер включает передачу данных и выделение памяти. Цель — менее 2 мс на операцию на согласованной Windows-машине с указанием распределения задержек. Патч движка и тесты поставляются вместе.
